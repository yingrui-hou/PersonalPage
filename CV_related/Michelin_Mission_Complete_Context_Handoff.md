## Production AI - Core Explanation

Production AI is not only a model exposed through an API. It is a controlled system:

```text
Business need
  -> measurable decision and acceptance criteria
  -> governed data contract
  -> reproducible training pipeline
  -> validated and versioned model artifact
  -> versioned API or batch interface
  -> tested immutable container image
  -> controlled deployment
  -> logs, metrics, dashboards and alerts
  -> incident response and rollback
  -> documentation, ownership and user training
  -> feedback, reassessment and retraining
```

Production readiness has several independent dimensions:

- **Model quality:** performance, calibration, uncertainty, robustness, and subgroup behaviour.
- **Data quality:** schema, missing values, ranges, units, freshness, lineage, and distribution shift.
- **Software quality:** tests, modularity, dependency management, reproducibility, security, and API compatibility.
- **Service quality:** availability, latency, throughput, resource usage, graceful failure, and recovery.
- **Operational quality:** ownership, dashboards, alerts, runbooks, deployment approval, rollback, and incident review.
- **Business quality:** outputs are usable, documented, understood, and connected to real decisions or BI workflows.

For the Michelin mission, model monitoring alone is insufficient. The team must know:

- whether the service is reachable;
- whether inputs remain valid;
- which code, model, schema, and configuration produced a prediction;
- what changed during deployment;
- whether model or data behaviour has shifted;
- who owns the alert;
- how to restore the previous stable version.
