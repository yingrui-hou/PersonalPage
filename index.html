01

ML under dataset shift

CatBoostReweightingCross-validation

Trained a CatBoost classifier to select rare signals, aligning simulated training data with measurements and choosing a threshold for the measurement objective.

Problem

Training data combined simulated signals and background from real measurements. Distribution differences and limited labelled samples required careful validation.

My contribution

  • Selected features using domain knowledge, correlation checks and feature importance.
  • Used reference measurements and hep_ml reweighting to address simulation–data differences before training.
  • Applied five-fold validation for feature selection and hyperparameter tuning; compared training and test responses using KS diagnostics.
  • Scanned the operating threshold with S / sqrt(S + B), using expected signal and background counts derived from fitted yields and selection efficiencies.

Validation and result

Applied the selected threshold to the analysis data and checked background suppression. Performance estimates came from the five-fold development validation; no additional untouched labelled holdout was available. Threshold efficiencies used pooled training and test events after compatible KS checks. These checks do not establish an independent final generalisation estimate.

Sensor simulation and test automation

Geant4MeasurementShell Automation

Connected prototype measurements to simulation and automated acquisition, calibration and initial data-quality checks.

Problem

Spatial variations in sensor response affected measurement resolution. The simulation needed measured response maps to represent the prototype realistically.

My contribution

  • Implemented sensor geometry and response models in Geant4/C++ and incorporated response maps derived from beam-test measurements.
  • Developed a Shell pipeline connecting existing readout, tracking and timing-calibration algorithms with storage and initial quality checks.
  • Participated in on-site setup and data acquisition; assisted subsequent fitting and measurement-effect corrections.

Validation and result

Compared simulated resolution with measured and uniform response maps. The prototype study quantified a non-uniformity contribution below 1% to the resolution’s constant term. The workflow connected physical tests, usable simulation inputs and design evaluation.

Calibrating classifier confidence

CalibrationDataset ShiftReal-Data Validation

Calibrated a classifier’s estimated error probabilities using reference measurements, then cross-checked the correction with simulation.

Problem

The classifier was trained on simulation whose distributions differed from real data. Its estimated error probabilities needed calibration for the target analysis.

My contribution

  • Selected suitable reference processes with identifiable classes and checked their relevance to the target data.
  • Aligned key input distributions through gradient-boosting reweighting where needed.
  • Fitted the relationship between predicted and observed misclassification probabilities and applied the correction to the target analysis.

Validation and result

Cross-checked the data-based calibration using reweighted target simulation; error estimates agreed within uncertainties. My contribution covered calibration and validation, with participation in training discussions. I did not train this model. The calibration is specific to the target process and reference-data conditions.

05

Signal decomposition for sensor design

Signal ProcessingSimulationDesign Validation

Used measured pulse profiles and simulation to assess whether signal components could be separated reliably and improve energy reconstruction.

Problem

Two candidate sensor materials produced overlapping light-pulse profiles. A reconstruction method could only work if the component signals remained distinguishable.

My contribution

  • Compared measured time profiles; engineers operated the measurement setup and sources.
  • Used measured timing parameters in simulation and fitted the resulting signals with component templates.
  • Checked parameter correlations and bias distributions to assess component recovery before applying an energy correction.

Validation and result

The study supported the team’s choice of ZnWO4: BGO profiles were insufficiently separated at low energies. One representative simulated correction study reduced a resolution term by about a factor of two. This result concerns that simulation study, not a measured gain in a deployed sensor.

TensorFlow migration and numerical verification

TensorFlowGPUNumerical Testing

Learned TensorFlow through an existing project, extended its numerical models and verified the calculations against a mature C++ implementation.

Problem

A collaborative measurement required new model components, realistic measurement effects and a working shared GPU environment.

My contribution

  • Started without TensorFlow knowledge, studied the inherited code and implemented new amplitude models plus efficiency, resolution and measurement-bias components.
  • Configured a shared GPU workstation in half a day; migrated the code to a successful GPU run in a further half-day. These timings cover setup and migration only.
  • Agreed component interfaces, reviewed GitLab merge requests and helped adjust weekly priorities. A collaborator developed the fitting component; I contributed to its testing.

Validation and result

Compared calculations at identical inputs against C++, traced discrepancies to variable types and obtained agreement at the required decimal precision. Used large simulated samples for stability checks and compared observable distributions with real data. During review, identified a sign error in the fitting component’s mathematical definition; we verified and corrected it together.

The software supported a joint BESIII–LHCb measurement. Repeated simulated experiments compared inference methods on the same fixed-size samples. The publications report about 5% lower statistical uncertainty for the LHCb result: a collaborative method outcome, not a software-speed gain.

Weak-signal analysis

Statistical ModellingUncertaintyValidation

Developed reusable Python/C++ analysis software to estimate a weak signal within noisy, mixed data.

Problem

The signal could not be identified reliably observation by observation. The analysis needed to estimate its contribution while accounting for background and measurement uncertainty.

My contribution

  • Built likelihood models to separate signal and background statistically.
  • Automated data selection, signal estimation and reference-sample comparisons in Python/C++/ROOT.
  • Checked variable correlations, fitted-parameter correlations and bias in repeated simulated experiments as part of each analysis’s uncertainty assessment.

Validation and result

Compared fit stability across datasets and selection settings. The checks performed found no problematic dependence or bias; the workflow supported a dedicated measurement. This is evidence of the checks performed, rather than a claim that every possible bias was excluded.
